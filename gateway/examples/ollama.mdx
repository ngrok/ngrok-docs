Ollama runs large language models (LLMs) on your own machine and serves them on `localhost:11434`.
That address only works on that machine.
Apps in the cloud, a laptop on another network, and tools like [Cursor](/gateway/examples/cursor-local-llm) can't reach it.

This guide shows you how to give Ollama a stable public HTTPS URL with ngrok and require a token, so only you and the apps you choose can call your models.
It works on every ngrok plan, including free.

<Warning>
Ollama has no built-in authentication.
Don't put it online without the token rule in step 2.
</Warning>

## What you'll need

- [Ollama](https://ollama.com/download) installed, with at least one model pulled, such as `ollama pull llama3.2`
- The [ngrok agent](https://download.ngrok.com) installed
- An [ngrok account](https://dashboard.ngrok.com/signup) and your [authtoken](https://dashboard.ngrok.com/get-started/your-authtoken)

## 1. Check that Ollama responds

Make sure Ollama is running and answers on its default port:

```bash
curl http://localhost:11434/v1/models
```

You should see a JSON list of the models you've pulled.

## 2. Create a Traffic Policy that requires a token

Generate a long random token:

```bash
openssl rand -hex 32
```

On the machine where Ollama runs, save this as `ollama.yaml`, replacing `YOUR_TOKEN` with the value you generated:

```yaml
on_http_request:
  - expressions:
      - "!hasReqHeader('Authorization') || getReqHeader('Authorization')[0] != 'Bearer YOUR_TOKEN'"
    actions:
      - type: deny
        config:
          status_code: 401
  - actions:
      - type: add-headers
        config:
          headers:
            host: localhost
```

**What's happening here?**
The first rule rejects any request that doesn't carry `Authorization: Bearer YOUR_TOKEN`.
ngrok enforces it in its cloud, so rejected requests never reach your machine.
The second rule rewrites the `Host` header to `localhost`, because Ollama rejects requests addressed to other hostnames.

A bearer token is what OpenAI-compatible clients send in their **API key** field, so the same token works in `curl`, the OpenAI SDKs, Cursor, and Open WebUI.

## 3. Put Ollama online

```bash
ngrok config add-authtoken <YOUR_AUTHTOKEN>
ngrok http 11434 --traffic-policy-file ollama.yaml
```

ngrok prints your public URL, such as `https://your-assigned-name.ngrok-free.dev`.
This is your account's [dev domain](/pricing-limits/free-plan-limits/).
It stays the same every time you restart `ngrok http`, so you configure each client once.

## 4. Try it out

From any machine, send a prompt to your model, replacing `YOUR_TOKEN` and the model name with your own:

```bash
curl https://your-assigned-name.ngrok-free.dev/v1/chat/completions \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
        "model": "llama3.2",
        "messages": [{"role": "user", "content": "Hello!"}]
      }'
```

Send the same request without the `Authorization` header and you get `401 Unauthorized`.

Open `http://localhost:4040` on the Ollama machine to watch each request and response in the ngrok inspector.

## 5. Connect your apps

Any app that speaks the OpenAI API can use your Ollama models.
Set its base URL to your ngrok URL plus `/v1`, and its API key to your token.

<Tabs>
  <Tab title="OpenAI SDK (Python)">
    ```python
    from openai import OpenAI

    client = OpenAI(
        base_url="https://your-assigned-name.ngrok-free.dev/v1",
        api_key="YOUR_TOKEN",
    )

    response = client.chat.completions.create(
        model="llama3.2",
        messages=[{"role": "user", "content": "Hello!"}],
    )
    print(response.choices[0].message.content)
    ```
  </Tab>
  <Tab title="Cursor">
    Cursor calls models from its own servers, so it needs a public URL.
    Follow [Use a local LLM in Cursor](/gateway/examples/cursor-local-llm).
  </Tab>
  <Tab title="Open WebUI">
    In **Admin Settings** > **Connections**, add an OpenAI API connection with your ngrok URL plus `/v1` and your token as the API key.
  </Tab>
</Tabs>

## Use a custom domain

On a paid plan, you can use your own domain, such as `llm.example.com`, instead of your dev domain.
[Reserve the domain](https://dashboard.ngrok.com/domains), then pass it with `--url`:

```bash
ngrok http 11434 --url https://llm.example.com --traffic-policy-file ollama.yaml
```

## Frequently asked questions

<AccordionGroup>
  <Accordion title="How do I access Ollama remotely?">
    Run `ngrok http 11434` with a Traffic Policy that requires a token, then call your ngrok URL from anywhere with `Authorization: Bearer YOUR_TOKEN`.
    Ollama keeps listening on `localhost`, so nothing on your machine is exposed beyond what ngrok lets through.
  </Accordion>
  <Accordion title="Why not set OLLAMA_HOST=0.0.0.0?">
    That makes Ollama listen on your local network, not the internet.
    It also has no authentication or HTTPS, so anyone on the same network can use your models.
    ngrok gives you a public HTTPS URL and enforces the token before traffic reaches your machine.
  </Accordion>
  <Accordion title="Does the URL change when I restart?">
    No.
    Every ngrok account, including free, gets a dev domain that `ngrok http` reuses on every run.
  </Accordion>
  <Accordion title="Why do I get a 403 from Ollama?">
    Ollama rejects requests whose `Host` header isn't `localhost`.
    Keep the `add-headers` rule in your policy, or start ngrok with `--host-header=localhost:11434` instead.
  </Accordion>
  <Accordion title="Does this work with LM Studio or vLLM?">
    Yes.
    Point `ngrok http` at their port instead, such as `1234` for LM Studio or `8000` for vLLM, and keep the token rule.
    To route across several model servers with failover, use the [AI Gateway](/ai-gateway/custom-providers/ollama).
  </Accordion>
</AccordionGroup>
