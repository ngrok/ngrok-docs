## Domain custom resource

### **apiVersion:** `ngrok.com/v1`

### **kind:** `Domain`

<Warning title="ingress.k8s.ngrok.com/v1alpha1 Domain is deprecated">
    `ngrok.com/v1` `Domain` replaces the deprecated `ingress.k8s.ngrok.com/v1alpha1` `Domain`. Only `spec.metadata` changed (now a map of strings).
    The Operator migrates the Domains it created; migrate your own before 1.1, and upgrade through both 0.25 and 1.0. See the [0.25 upgrade guide](https://github.com/ngrok/ngrok-operator/blob/main/docs/upgrading-to-0.25.md).
</Warning>

Domains define the hostnames that should be reserved for your ngrok endpoints.
They are automatically created by the controller based on the `Ingress`, `Gateway`, `CloudEndpoint` and `AgentEndpoint` custom resources you create.
Standard ngrok subdomains will automatically be created and reserved for you.
Custom domains will also be created and reserved, but will be up to you to configure the DNS records for them.
See the [custom domain](/gateway/k8s/guides/custom-domain) guide for more details.

If you delete all the `Ingress`/`Gateway`/`CloudEndpoint`/`AgentEndpoint` objects for a particular host, as a safety precaution, the Operator does _NOT_ delete the domains and thus does not unregister them.
This ensures you don't lose domains while modifying or recreating ingress objects.
You can still manually delete a `Domain` resource via `kubectl delete domains.ngrok.com <name>`. Its `spec.reclaimPolicy` controls whether the reservation is released in ngrok.

## Domain structure and types

The following outlines the high level structure and typings of a `Domain`

```yaml
apiVersion: ngrok.com/v1
kind: Domain
metadata:
  name: <string>
  namespace: <string>
spec:
  description: <string>         # optional, default: "Created by ngrok-operator"
  metadata: <map[string]string> # optional, default: {"owned-by": "ngrok-operator"}
  domain: <string>              # required, immutable
  resolvesTo:                   # optional
  - value: <string>             # required
  reclaimPolicy: <string>       # optional, default: "Delete"
```

## Domain fields

The following sections outline each field of the `Domain` custom resource, whether they are required, what their default values are (if applicable), and a description of their purpose/constraints.

### `spec`

`spec` defines the desired state of the `Domain`

**Type:** `Object`

**Required:** yes

**Default:** none

**Fields:**

| Field Name                                 | Type                | Required | Default                           | Description                                                                         |
| ------------------------------------------ | ------------------- | -------- | --------------------------------- | ----------------------------------------------------------------------------------- |
| [`spec.description`](#specdescription)     | `string`            | no       | `"Created by ngrok-operator"`     | Human-readable description for this `Domain` to help identify/describe it           |
| [`spec.metadata`](#specmetadata)           | `map[string]string` | no       | `{"owned-by": "ngrok-operator"}`  | Arbitrary key/value data associated with the object in the ngrok API/dashboard      |
| [`spec.domain`](#specdomain)               | `string`            | yes      | none                              | The domain name to reserve                                                          |
| [`spec.resolvesTo`](#specresolvesto)       | `[]Object`          | no       | none                              | The list of resolving targets for the domain                                        |
| [`spec.reclaimPolicy`](#specreclaimpolicy) | `string` (enum)     | no       | `"Delete"`                        | Whether to release the reservation in ngrok when the `Domain` is deleted            |

### `spec.description`

Human-readable description of this domain that can be used to help identify/describe it.

**Type:** `string`

**Required:** no

**Default:** `"Created by ngrok-operator"`

### `spec.metadata`

Arbitrary key/value data associated with the object in the ngrok API/dashboard.
Values must be strings.

**Type:** `map[string]string`

**Required:** no

**Default:** `{"owned-by": "ngrok-operator"}`

### `spec.domain`

The domain name to reserve. example: `example-domain.ngrok.app`

This field is immutable. Reserved domains cannot be renamed through the ngrok API, so changing `spec.domain` on an existing `Domain` is rejected.
To reserve a different domain, create a new `Domain` resource.

**Type:** `string`

**Required:** yes

**Default:** none

### `spec.resolvesTo`

The list of resolving targets for the domain.
Each entry has a single required `value` field: a point-of-presence alias.

**Type:** `[]Object`

**Required:** no

**Default:** none

### `spec.reclaimPolicy`

The policy to apply to the reservation in ngrok when the `Domain` is deleted.
`Delete` releases the reservation, and `Retain` keeps it in your ngrok account.
The Operator sets this on the `Domain` resources it creates from the `ngrok.features.domains.defaultReclaimPolicy` Helm value.

**Type:** `string (enum)`

**Required:** no

**Default:** `"Delete"`

**Allowed Values:** `"Delete"`, `"Retain"`

## Status fields

The `Domain` resource includes status information that reflects the current state of the domain in the ngrok system.

### `status.observedGeneration`

The most recent `metadata.generation` the Operator observed. When it matches `metadata.generation`, the status reflects the latest spec.

**Type:** `int64`

### `status.id`

The ngrok API ID for this domain.

**Type:** `string`

**Example:** `rd_347Xxo1moBQ5AgBmI3a9CFgcCrk`

### `status.domain`

The hostname this `Domain` represents.
This is the reserved domain, or this `Domain`'s own hostname when it's covered by a wildcard reservation.

**Type:** `string`

**Example:** `example-domain.ngrok.app`

### `status.coveredByWildcardDomain`

The wildcard reservation that already serves this hostname, for example `*.example.com` for `a.example.com`.
When set, the Operator doesn't reserve the hostname because the wildcard already covers it, and `status.id` stays empty.

**Type:** `Object`

**Fields:**
- `id` - The ngrok API ID of the wildcard reservation
- `domain` - The wildcard domain name

**Example:**
```yaml
coveredByWildcardDomain:
  id: rd_347Xxo1moBQ5AgBmI3a9CFgcCrk
  domain: "*.example.com"
```

### `status.resolvesTo`

The list of resolving targets for the domain.

**Type:** `[]Object`

### `status.cnameTarget`

The CNAME target for custom domains. This field is only populated for custom (non-ngrok) domains and indicates where you should point your DNS records.

**Type:** `string`

**Example:** `exampledata.otherdata.ngrok-cname.com`

### `status.acmeChallengeCNAMETarget`

The CNAME target for the ACME challenge. This field is only populated for wildcard domains.

**Type:** `string`

### `status.certificate`

Information about the TLS certificate for the domain.

**Type:** `Object`

**Fields:**
- `id` - The certificate ID

### `status.certificateManagementPolicy`

The certificate management configuration for the domain.

**Type:** `Object`

**Fields:**
- `authority` - The certificate authority, for example `letsencrypt`
- `privateKeyType` - The private key type, for example `ecdsa`

### `status.certificateManagementStatus`

The certificate management status for the domain.

**Type:** `Object`

**Fields:**
- `renewsAt` - When the certificate will be renewed
- `provisioningJob` - The current provisioning job, with `errorCode`, `message`, `startedAt`, and `retriesAt` fields

### `status.conditions`

Standard Kubernetes conditions that indicate the state of the domain.

**Type:** `[]Condition`

Each condition includes:
- `type` - The condition type
- `status` - `True`, `False`, or `Unknown`
- `reason` - A programmatic identifier for the condition state
- `message` - A human-readable description
- `lastTransitionTime` - When the condition last changed
- `observedGeneration` - The resource generation this condition applies to

#### Condition types

##### `Ready`

Indicates whether the domain is fully operational and ready to use for endpoints.

**Status Values:**
- `True` - Domain is active and ready
- `False` - Domain is not ready (see reason for details)

**Reasons:**

| Reason | Status | Meaning |
|--------|--------|---------|
| `DomainActive` | `True` | Domain is successfully reserved and ready to use |
| `CoveredByWildcardDomain` | `True` | Domain is ready to use because a wildcard reservation covers it |
| `DomainInvalid` | `False` | Domain format or configuration is invalid |
| `DomainCreationFailed` | `False` | Failed to reserve the domain in ngrok |
| `ProvisioningError` | `False` | Error provisioning custom domain (DNS/certificate issues) |

**Example:**
```yaml
conditions:
- type: Ready
  status: "True"
  reason: DomainActive
  message: "Domain ready for use"
  lastTransitionTime: "2025-10-29T00:39:15Z"
  observedGeneration: 1
```

##### `DomainCreated`

Indicates whether the domain was successfully reserved in the ngrok API.

**Status Values:**
- `True` - Domain was successfully reserved, or is covered by a wildcard reservation
- `False` - Failed to reserve domain

**Reasons:**

| Reason | Status | Meaning |
|--------|--------|---------|
| `DomainCreated` | `True` | Domain successfully reserved |
| `CoveredByWildcardDomain` | `True` | Reservation skipped because a wildcard reservation already covers the domain |
| `DomainCreationFailed` | `False` | API call to reserve domain failed |
| `DomainInvalid` | `False` | Domain name or format is invalid |

**Example:**
```yaml
conditions:
- type: DomainCreated
  status: "True"
  reason: DomainCreated
  message: "Domain successfully reserved"
  lastTransitionTime: "2025-10-29T00:39:15Z"
  observedGeneration: 1
```

##### `CertificateReady`

Indicates whether the TLS certificate for the domain is ready.

**Status Values:**
- `True` - Certificate is ready or managed by ngrok
- `False` - Certificate is not ready

**Reasons:**

| Reason | Status | Meaning |
|--------|--------|---------|
| `NgrokManaged` | `True` | Certificate is automatically managed by ngrok |
| `CertificateReady` | `True` | Custom certificate is provisioned and ready |
| `ProvisioningError` | `False` | Error provisioning custom domain certificate |
| `DomainCreationFailed` | `False` | Cannot provision certificate because domain creation failed |
| `DomainInvalid` | `False` | Cannot provision certificate because domain is invalid |

**Example:**
```yaml
conditions:
- type: CertificateReady
  status: "True"
  reason: NgrokManaged
  message: "Certificate managed by ngrok"
  lastTransitionTime: "2025-10-29T00:39:15Z"
  observedGeneration: 1
```

##### `DNSConfigured`

Indicates whether DNS is properly configured for the domain.

**Status Values:**
- `True` - DNS is configured correctly
- `False` - DNS configuration is incomplete or incorrect

**Reasons:**

| Reason | Status | Meaning |
|--------|--------|---------|
| `NgrokManaged` | `True` | DNS is automatically managed by ngrok (ngrok subdomain) |
| `DomainCreated` | `True` | DNS records have been configured for custom domain |
| `ProvisioningError` | `False` | DNS records are not pointing to ngrok infrastructure |
| `DomainCreationFailed` | `False` | Cannot configure DNS because domain creation failed |
| `DomainInvalid` | `False` | Cannot configure DNS because domain is invalid |

**Example:**
```yaml
conditions:
- type: DNSConfigured
  status: "True"
  reason: NgrokManaged
  message: "DNS managed by ngrok"
  lastTransitionTime: "2025-10-29T00:39:15Z"
  observedGeneration: 1
```

**Example (Custom Domain DNS Error):**
```yaml
conditions:
- type: DNSConfigured
  status: "False"
  reason: ProvisioningError
  message: "DNS_ERROR Reserved domain \"example.com\" NS DNS records are not pointing at the ngrok infrastructure"
  lastTransitionTime: "2025-10-29T00:39:24Z"
  observedGeneration: 1
```

## Status examples

### Successfully reserved ngrok subdomain

```yaml
status:
  id: rd_347Xxo1moBQ5AgBmI3a9CFgcCrk
  domain: example-domain.ngrok.app
  conditions:
  - type: DomainCreated
    status: "True"
    reason: DomainCreated
    message: "Domain successfully reserved"
    lastTransitionTime: "2025-10-29T00:39:15Z"
    observedGeneration: 1
  - type: CertificateReady
    status: "True"
    reason: NgrokManaged
    message: "Certificate managed by ngrok"
    lastTransitionTime: "2025-10-29T00:39:15Z"
    observedGeneration: 1
  - type: DNSConfigured
    status: "True"
    reason: NgrokManaged
    message: "DNS managed by ngrok"
    lastTransitionTime: "2025-10-29T00:39:15Z"
    observedGeneration: 1
  - type: Ready
    status: "True"
    reason: DomainActive
    message: "Domain ready for use"
    lastTransitionTime: "2025-10-29T00:39:15Z"
    observedGeneration: 1
```

### Custom domain with DNS error

```yaml
status:
  domain: "*.wildcard-test.example.com"
  cnameTarget: "exampledata.otherdata.ngrok-cname.com"
  conditions:
  - type: DomainCreated
    status: "True"
    reason: DomainCreated
    message: "Domain successfully reserved"
    lastTransitionTime: "2025-10-29T00:39:24Z"
    observedGeneration: 1
  - type: DNSConfigured
    status: "False"
    reason: ProvisioningError
    message: 'DNS_ERROR Reserved domain "*.wildcard-test.example.com" NS DNS records are not pointing at the ngrok infrastructure'
    lastTransitionTime: "2025-10-29T00:39:24Z"
    observedGeneration: 1
  - type: CertificateReady
    status: "False"
    reason: ProvisioningError
    message: "Cannot provision certificate until DNS is configured"
    lastTransitionTime: "2025-10-29T00:39:24Z"
    observedGeneration: 1
  - type: Ready
    status: "False"
    reason: ProvisioningError
    message: "Domain not ready due to DNS configuration error"
    lastTransitionTime: "2025-10-29T00:39:24Z"
    observedGeneration: 1
```

### Domain covered by a wildcard reservation

```yaml
status:
  domain: a.example.com
  coveredByWildcardDomain:
    id: rd_347Xxo1moBQ5AgBmI3a9CFgcCrk
    domain: "*.example.com"
  conditions:
  - type: DomainCreated
    status: "True"
    reason: CoveredByWildcardDomain
    message: "Reservation skipped: already covered by wildcard domain *.example.com"
    lastTransitionTime: "2025-10-29T00:39:15Z"
    observedGeneration: 1
  - type: Ready
    status: "True"
    reason: CoveredByWildcardDomain
    message: "Domain ready for use (covered by wildcard domain *.example.com)"
    lastTransitionTime: "2025-10-29T00:39:15Z"
    observedGeneration: 1
```

## Checking domain status

You can check the status of a domain using kubectl:

```bash
# Check if domain is ready
kubectl get domains.ngrok.com example-domain -o jsonpath='{.status.conditions[?(@.type=="Ready")]}'

# Watch for domain to become ready
kubectl wait --for=condition=Ready domains.ngrok.com/example-domain --timeout=60s

# Get all domains with their ready status
kubectl get domains.ngrok.com -A -o custom-columns=\
NAME:.metadata.name,\
DOMAIN:.status.domain,\
READY:.status.conditions[?(@.type==\'Ready\')].status,\
REASON:.status.conditions[?(@.type==\'Ready\')].reason
```

## Example domain

```yaml
apiVersion: ngrok.com/v1
kind: Domain
metadata:
  name: example-domain
  namespace: default
spec:
  description: Created by ngrok-operator
  domain: example-domain.ngrok.app
  metadata:
    owned-by: ngrok-operator
  reclaimPolicy: Retain
```
