Redirects allow you to seamlessly route users from one URL to another, ensuring they always reach the correct destination.
They're commonly used for:

🔄 Preserving SEO rankings when URLs change. <br />
🔐 Enforcing secure HTTPS connections. <br />
🌍 Directing traffic to localized versions of a site. <br />


## 🔍 What are the benefits of redirects?

Redirects help optimize user experience and security by ensuring that visitors always land on the correct and most relevant page.

Key benefits:

- **Ensure Seamless URL Changes:** Automatically direct users to new pages when URLs change.
- **Enforce HTTPS:** Redirect HTTP traffic to secure HTTPS connections.
- **Improve SEO & Preserve Link Equity:** Avoid broken links that impact search engine rankings.
- **Handle Legacy URLs:** Maintain compatibility with old URLs or deprecated endpoints.
- **Enhance User Experience:** Automatically direct visitors to localized or mobile-friendly versions of your site.


## Redirect full path

The following examples showcase how to create an endpoint that redirects requests.
The hostname, scheme, and port are kept the same, but the entire path of the request is changed.
- Requests to `https://example-hostname.ngrok.app/example` redirect to `https://example-hostname.ngrok.app/redirect`
- Requests to `https://example-hostname.ngrok.app/example/foo` redirect to `https://example-hostname.ngrok.app/redirect`

<Tabs>
<Tab title="AgentEndpoint">
Check out the [redirect Traffic Policy action](/gateway/traffic-policy/actions/redirect/) page for more details about how it functions and the parameters it accepts.

```yaml
apiVersion: ngrok.com/v1
kind: AgentEndpoint
metadata:
  name: example-agent-endpoint
spec:
  url: https://example-hostname.ngrok.app
  upstream:
    url: http://my-service.my-namespace:8080
  trafficPolicy:
    inline:
      on_http_request:
        - actions:
            - type: redirect
              config:
                from: /.*
                to: /redirect
```
</Tab>
<Tab title="CloudEndpoint">
Check out the [redirect Traffic Policy action](/gateway/traffic-policy/actions/redirect/) page for more details about how it functions and the parameters it accepts.

```yaml
apiVersion: ngrok.com/v1
kind: CloudEndpoint
metadata:
  name: example-cloud-endpoint
spec:
  url: https://example-hostname.ngrok.app
  trafficPolicy:
    inline:
      on_http_request:
        - actions:
            - type: redirect
              config:
                from: /.*
                to: /redirect
```
</Tab>
<Tab title="Ingress">
💡 Ingress resources don't have native redirect capabilities, but you can extend them using a Traffic Policy.
Check out the [redirect Traffic Policy action](/gateway/traffic-policy/actions/redirect/) page for more information about how to customize the parameters.

<Steps titleSize="h3">
  <Step title="Create a TrafficPolicy">

    ```yaml
    apiVersion: ngrok.com/v1
    kind: TrafficPolicy
    metadata:
      name: example-tp
      namespace: default
    spec:
      policy:
        on_http_request:
          - actions:
              - type: redirect
                config:
                  from: /.*
                  to: /redirect
    ```
  </Step>

  <Step title="Use the TrafficPolicy on an Ingress">

    ```yaml
    apiVersion: networking.k8s.io/v1
    kind: Ingress
    metadata:
      annotations:
        ngrok.com/traffic-policy: example-tp
      name: example-ingress
      namespace: default
    spec:
      ingressClassName: ngrok
      rules:
        - host: example-hostname.ngrok.app
          http:
            paths:
              - path: /
                pathType: Prefix
                backend:
                  service:
                    name: example-service
                    port:
                      number: 80
    ```
  </Step>
</Steps>
</Tab>
<Tab title="Gateway API">
✅ Gateway API natively supports redirect configuration, and this feature is fully supported by the ngrok Kubernetes Operator.

<Steps titleSize="h3">
  <Step title="Create a Gateway">

    If you already have a `Gateway`, you can use that instead.

    ```yaml
    apiVersion: gateway.networking.k8s.io/v1
    kind: Gateway
    metadata:
      name: example-gateway
      namespace: default
    spec:
      gatewayClassName: ngrok
      listeners:
        - name: example
          hostname: "example-hostname.ngrok.app"
          port: 443
          protocol: HTTPS
    ```
  </Step>

  <Step title="Create an HTTPRoute with a RequestRedirect filter">

    ```yaml
    apiVersion: gateway.networking.k8s.io/v1
    kind: HTTPRoute
    metadata:
      name: example-route
      namespace: default
    spec:
      hostnames:
      - example-hostname.ngrok.app
      parentRefs:
      - group: gateway.networking.k8s.io
        kind: Gateway
        name: example-gateway
        namespace: default
      rules:
      - matches:
        - path:
            type: PathPrefix
            value: /example
        filters:
        - type: RequestRedirect
          requestRedirect:
            path: 
              type: ReplaceFullPath
              replaceFullPath: "/redirect"
    ```
  </Step>
</Steps>
</Tab>
</Tabs>
