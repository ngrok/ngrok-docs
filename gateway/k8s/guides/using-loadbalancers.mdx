## How the ngrok Operator uses LoadBalancer services

By default, the Operator exposes services of type `LoadBalancer` using a TCP Endpoint.
The Operator automatically creates a reserved address for the service and updates the service's status with the reserved address.
You can use other projects like [external-dns](https://github.com/ngrok/ngrok-operator/blob/main/docs/examples/external-dns/README.md) to create a CNAME record for the reserved address automatically.

See the [TCP Endpoint](/gateway/endpoints/tcp/) and [TLS Endpoint](/gateway/endpoints/tls/) pages for more information about how ngrok handles these kinds of endpoints.

For example, the Operator exposes the following `LoadBalancer` service using a TCP Endpoint.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mysite
spec:
  allocateLoadBalancerNodePorts: false # ngrok's tunneling technology does not require NodePorts to be allocated.
  loadBalancerClass: ngrok
  type: LoadBalancer
  selector:
    app: mysite
  ports:
    - name: traffic
      port: 9000
      protocol: TCP
      targetPort: 9000
```

If you'd like a TLS Endpoint instead, the following example shows how to create one.
Set the `ngrok.com/url` annotation to a `tls://` URL with your domain to expose the service as a TLS Endpoint.
The endpoint passes TLS traffic through to your service without terminating it, so the service must serve TLS itself.
Once the reserved domain is ready and the endpoint is created, the Operator updates the service's status with the ngrok address.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mysite
  annotations:
    ngrok.com/url: tls://mysite.mydomain.com # Required to use TLS
    external-dns.alpha.kubernetes.io/hostname: "mysite.mydomain.com"
spec:
  allocateLoadBalancerNodePorts: false # ngrok's tunneling technology does not require NodePorts to be allocated.
  loadBalancerClass: ngrok
  type: LoadBalancer
  selector:
    app: mysite
  ports:
    - name: traffic
      port: 9000
      protocol: TCP
      targetPort: 9000
```

While using Services offers simplicity, using the `CloudEndpoint` and `AgentEndpoint` resources directly instead of translating `LoadBalancer` services into them using the Operator offers more configuration options and flexibility for configuring TCP and TLS endpoints.
