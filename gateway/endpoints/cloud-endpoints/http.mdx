This page covers what is specific to HTTP/S Cloud Endpoints.
For HTTP/S behavior, limits, observability, and examples shared with Agent Endpoints, see the [HTTP/S Agent Endpoint reference](/gateway/endpoints/http).

## Create an HTTP/S Cloud Endpoint

Follow the [Cloud Endpoints Quickstart](/getting-started/cloud-endpoints-quickstart) to create an endpoint in the dashboard or API.
For an HTTP/S Cloud Endpoint, provide a complete `http://` or `https://` URL and a Traffic Policy.

## URL

An HTTP/S Cloud Endpoint URL must include a scheme and hostname.
Use port `80` for `http` and port `443` for `https`.
The hostname must match a [Domain](/gateway/domains/) in your account.

See [Public Endpoint URLs](/gateway/endpoints/public-endpoints/#urls) for accepted URL formats, and [Domains](/gateway/domains/) to configure custom or wildcard domains.

## Traffic Policy

Every Cloud Endpoint requires a [Traffic Policy](/gateway/traffic-policy/) to handle incoming traffic.
Unlike an Agent Endpoint, a Cloud Endpoint does not implicitly forward traffic to the agent that created it.
Use a policy action such as `forward-internal`, `custom-response`, `redirect`, or `deny` to handle the request.

For examples, see the [Cloud Endpoints Quickstart](/getting-started/cloud-endpoints-quickstart) and the [Traffic Policy action reference](/gateway/traffic-policy/actions/).
