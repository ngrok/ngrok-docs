An HTTP/S Cloud Endpoint accepts HTTP and HTTPS traffic and stays online until you delete it.
It behaves like an [HTTP/S Agent Endpoint](/gateway/endpoints/http), except that its Traffic Policy decides where traffic goes instead of an agent.

## Create an HTTP/S Cloud Endpoint

Follow the [Cloud Endpoints Quickstart](/getting-started/cloud-endpoints-quickstart) to create an endpoint in the dashboard or with the API.

An HTTP/S Cloud Endpoint URL must include a scheme and hostname.
Use port `80` for `http` and port `443` for `https`.
The hostname must match a [domain](/gateway/domains/) in your account, which can be a custom or wildcard domain.
See [Public Endpoint URLs](/gateway/endpoints/public-endpoints/#urls) for accepted URL formats.

## Traffic Policy

Every Cloud Endpoint requires a [Traffic Policy](/gateway/traffic-policy/) to handle incoming traffic.
Unlike an Agent Endpoint, a Cloud Endpoint doesn't implicitly forward traffic to the agent that created it.
Use a policy action such as `forward-internal`, `custom-response`, `redirect`, or `deny` to handle each request.
See the [Traffic Policy action reference](/gateway/traffic-policy/actions/) for every action.

## Pricing

HTTP/S Cloud Endpoints are billed as [endpoint usage](/pricing-limits/#endpoint-limits), and custom and wildcard domains are billed as [domains](/gateway/domains/#pricing).
