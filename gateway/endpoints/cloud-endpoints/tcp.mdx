A TCP Cloud Endpoint accepts raw TCP traffic at a fixed address and stays online until you delete it.
It behaves like a [TCP Agent Endpoint](/gateway/endpoints/tcp), except that its Traffic Policy decides where traffic goes instead of an agent.

## Create a TCP Cloud Endpoint

A public TCP Cloud Endpoint needs a reserved [TCP Address](/gateway/domains/tcp-addresses/), which gives it a fixed hostname and port such as `1.tcp.ngrok.io:12345`.
Endpoints on the `internal` or `kubernetes` binding don't need one.

After you reserve an address, create the endpoint with that address and a Traffic Policy:

```bash title="Command line"
ngrok api endpoints create \
  --url tcp://{your-tcp-address}.ngrok.io:{your-port} \
  --traffic-policy "$(<traffic-policy.yml)"
```

The [Cloud Endpoints Quickstart](/getting-started/cloud-endpoints-quickstart) walks through the same steps in the dashboard.

## Traffic Policy

Every Cloud Endpoint requires a [Traffic Policy](/gateway/traffic-policy/) to handle incoming traffic.
For TCP endpoints, you can restrict access with [IP Restriction](/gateway/traffic-policy/actions/restrict-ips/) or [Mutual TLS](/gateway/traffic-policy/actions/terminate-tls/).

## Pricing

TCP Cloud Endpoints are billed as [endpoint usage](/pricing-limits/#endpoint-limits), and each reserved address is billed as a [TCP Address](/gateway/domains/tcp-addresses/#pricing).
