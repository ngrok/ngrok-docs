A **Cloud Endpoint** is managed centrally and stays online until you delete it.
Unlike an [Agent Endpoint](/gateway/endpoints/agent-endpoints), its lifetime does not depend on an agent session.

Use a Cloud Endpoint when you need a persistent address or want to manage its [Traffic Policy](/gateway/traffic-policy/) through the dashboard or API.
A Cloud Endpoint requires a Traffic Policy to handle incoming traffic, for example by forwarding it to an [internal endpoint](/gateway/endpoints/internal-endpoints/) or returning a response.

## Create a Cloud Endpoint

Follow the [Cloud Endpoints Quickstart](/getting-started/cloud-endpoints-quickstart) to create a Cloud Endpoint in the dashboard or with the API.
Specify a fully qualified URL and a Traffic Policy when you create the endpoint.
You can also manage Cloud Endpoints with the Kubernetes Operator's [`CloudEndpoint` CRD](/gateway/k8s/crds/).

## Configure a Cloud Endpoint

Choose an endpoint [protocol](/gateway/endpoints/protocols) and [binding](/gateway/endpoints/bindings) for the traffic you want to accept.
The [HTTP/S](/gateway/endpoints/cloud-endpoints/http), [TLS](/gateway/endpoints/cloud-endpoints/tls), and [TCP](/gateway/endpoints/cloud-endpoints/tcp) guides cover Cloud Endpoint-specific behavior and configuration.

## API representation

The Endpoints API identifies Cloud Endpoints with `type: cloud` and a `null` `tunnel_session` value.
