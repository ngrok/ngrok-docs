An **Agent Endpoint** is created by an ngrok agent and remains online while that agent is connected.
By default, it forwards traffic to the service configured by the agent.

Use an Agent Endpoint when the service is reachable from an agent, including a local development server, a private network, or a Kubernetes cluster.
For an endpoint managed centrally through the dashboard or API, see [Cloud Endpoints](/gateway/endpoints/cloud-endpoints/).

## Create an Agent Endpoint

Follow the [Agent CLI Quickstart](/gateway/endpoints/agent-cli-quickstart/) to expose a service with the Agent CLI.
You can also create Agent Endpoints with [Agent SDKs](/agent-sdks/) or the [Kubernetes Operator](/gateway/k8s/).

## Configure an Agent Endpoint

Choose an endpoint [protocol](/gateway/endpoints/protocols) and [binding](/gateway/endpoints/bindings) for the traffic you want to accept.
Traffic Policy is optional for Agent Endpoints.
When present, it can authenticate or route traffic before forwarding requests that it does not terminate to the agent.

The [HTTP/S](/gateway/endpoints/http), [TLS](/gateway/endpoints/tls), [TCP](/gateway/endpoints/tcp), and [internal endpoint](/gateway/endpoints/internal-endpoints) guides explain their Agent Endpoint-specific behavior and configuration.

## API representation

The Endpoints API identifies Agent Endpoints with `type: agent` and includes a `tunnel_session` reference to the session that created them.
The API and dashboard provide a read-only view; the agent manages the endpoint configuration.

## Manage Agent Endpoints

You can inspect endpoints through the dashboard and the [`/endpoints` API resource](/api-reference/endpoints/list).

See [Endpoint Pooling](/gateway/endpoints/endpoint-pooling) to distribute traffic across Agent Endpoints that share a URL and binding.
