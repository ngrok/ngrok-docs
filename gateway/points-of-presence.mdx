ngrok's globally distributed cloud service runs on points of presence all around the world to enable fast, low-latency traffic to your applications.

ngrok continuously expands regional points of presence.
As ngrok adds each new point of presence, your applications become faster for global customers without any changes.

## Reference

The current points of presence are:

| Code       | Location                   |
| ---------- | -------------------------- |
| `ap`       | Asia/Pacific (Singapore)   |
| `au`       | Australia (Sydney)         |
| `eu`       | Europe (Frankfurt)         |
| `in`       | India (Mumbai)             |
| `jp`       | Japan (Tokyo)              |
| `sa`       | South America (São Paulo)  |
| `us`       | United States (Ohio)       |
| `us-cal-1` | United States (California) |

## Usage

ngrok uses the region codes in the reference table throughout the product to communicate which points of presence a particular feature uses and to let you configure pieces of the product to use specific points of presence.
The following features use region codes:

- [Global Load Balancer](/gateway/domains/global-load-balancer/)
- [`conn.server_region` Traffic Policy variable](/gateway/traffic-policy/variables/connection/#connserver-region)
- [`region` Agent Configuration property](/gateway/agent/config/v2/#region)
- [Domain Global Load Balancer configuration](/domains#global-load-balancer)

The following APIs use them correspondingly:

- [Domain `resolves_to` property](/api-reference/reserveddomains/create), used for [region pinning](/gateway/domains/region-pinning)
- [TCP Address `region` property](/api-reference/reservedaddrs/list)
- [Tunnel Sessions `region` property](/api-reference/tunnelsessions/list)
