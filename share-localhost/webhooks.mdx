Webhooks require a publicly accessible URL, which makes local development tricky.
ngrok solves this by giving your local server a public HTTPS endpoint that webhook providers can deliver events to.

## How it works

1. [Install ngrok](https://ngrok.com/download)
2. Start your local webhook handler on any port
3. Run `ngrok http <port>` to create a public URL
4. Register the ngrok URL with your webhook provider
5. Receive webhook events directly on your local machine

## Quick example

```bash
ngrok http 8080
```

Copy the HTTPS forwarding URL from the agent console and paste it into your webhook provider's configuration (for example, Stripe, GitHub, or Twilio).

### Start the endpoint from your app

If your webhook handler is a Next.js or FastAPI app, a [framework library](/agent-sdks/frameworks/) opens the endpoint when your app starts.
There's no separate agent to install or keep running in another terminal.

<Tabs>
  <Tab title="Next.js">
    ```bash
    npx @ngrok/nextjs dev
    ```

    The command starts `next dev`, prints the public URL, and reminds you to register it with your webhook provider.
    See the [Next.js library](/agent-sdks/frameworks/nextjs) for setup.
  </Tab>
  <Tab title="FastAPI">
    ```python title="main.py"
    import ngrok_fastapi
    from fastapi import FastAPI, Request

    app = FastAPI()
    ngrok_fastapi.attach(app, ngrok_fastapi.Config(port=8000))


    @app.post("/webhooks")
    async def webhooks(request: Request):
        event = await request.json()
        return {"received": True}
    ```

    Run the app with `uvicorn main:app --port 8000`, and the library prints the public URL.
    See the [FastAPI library](/agent-sdks/frameworks/fastapi) for setup.
  </Tab>
</Tabs>

## Inspect webhook payloads

ngrok's built-in [Traffic Inspector](/share-localhost/inspection) lets you see every webhook request in real time, including headers, body, and response.
This makes it easy to debug webhook integrations without adding logging to your application.

## Replay failed webhooks

Instead of waiting for the webhook provider to retry a failed delivery, you can [replay the request](/share-localhost/inspection#how-replays-work) instantly from the Traffic Inspector.
This dramatically speeds up the development cycle when building webhook handlers.

## Verify webhook signatures

Webhook providers sign each request with a secret so you can confirm it's authentic.
Instead of writing verification logic in your application, you can use the [verify-webhook Traffic Policy action](/gateway/traffic-policy/actions/verify-webhook/) to validate incoming webhook signatures and confirm requests originate from the expected provider.

Add a `verify-webhook` action to your Traffic Policy configuration with your provider name and signing secret:

```yaml title="policy.yml"
on_http_request:
  - actions:
      - type: verify-webhook
        config:
          provider: gitlab
          secret: secret!
      - type: custom-response
        config:
          status_code: 200
          headers:
            content-type: text/plain
          body: GitLab webhook verified
```

Then start your endpoint with the policy file:

<Tabs>
  <Tab title="Agent CLI">
    ```bash
    ngrok http 8080 --traffic-policy-file /path/to/policy.yml
    ```
  </Tab>
  <Tab title="Next.js">
    ```ts title="ngrok.config.ts"
    import { readFileSync } from "node:fs";

    export default {
      trafficPolicy: readFileSync("policy.yml", "utf8"),
    };
    ```

    Then run `npx @ngrok/nextjs dev`.
  </Tab>
  <Tab title="FastAPI">
    ```python title="main.py"
    from pathlib import Path

    ngrok_fastapi.attach(app, ngrok_fastapi.Config(
        port=8000,
        traffic_policy=Path("policy.yml").read_text(),
    ))
    ```
  </Tab>
</Tabs>

If verification succeeds, the request proceeds to the next action defined in your Traffic Policy, which in this case sends a custom HTTP response.
If it fails, ngrok terminates the request with a `403 Forbidden` response.

### Debugging

When debugging, testing, and crafting custom responses, you may want to allow further Traffic Policy actions to be processed even if the webhook signature isn't verified.
To do so, set `enforce` to `false`:

```yaml title="policy.yml" {6}
on_http_request:
  - actions:
      - type: verify-webhook
        config:
          provider: github
          secret: your-webhook-secret
          enforce: false
```

With `enforce: false`, unverified requests still reach your server, but you can inspect the verification result using [action result variables](/gateway/traffic-policy/actions/verify-webhook/#action-result-variables) in subsequent actions.

### Supported providers for webhook verification

The `verify-webhook` action supports [many providers](/gateway/traffic-policy/actions/verify-webhook/#supported-providers), including GitHub, Stripe, Shopify, Slack, and Twilio.
