## Overview

Service Users (previously called Bot Users) are similar to [Users](/iam/users/) but they're intended for automated systems that programmatically interact with your ngrok accounts, either by starting ngrok Agents or making requests to the API.
Service Users own a set of credentials (authtokens, API keys, and SSH keys) that they use to authenticate with ngrok.

<Info>
Other platforms sometimes call this concept a _service account_.
</Info>

You can see and manage your Service Users in the [ngrok Dashboard](https://dashboard.ngrok.com/service-users).

## When to use a Service User

Use Service Users whenever an automated process uses your ngrok account.
Service Users are the best choice in these circumstances because they guarantee that your agents or programs continue working after the user who set them up leaves your account.
When a user leaves an account, ngrok revokes all of their credentials; setting up Service Users for those services helps you avoid downtime and impact to your production services.

## Differences from users

Service Users function exactly like Users with a few exceptions:

- Service Users may not log into the Dashboard.
- Service Users can hold only a few [roles](#role-based-access-control), and never the Administrator role.
- Service Users may not be a member of more than one Account.
  If you are on a free plan, ngrok doesn't count Service Users when it computes how many seats to charge you for.

### Role-based access control

Every Service User holds at least one role.
New Service Users get the `developer` role unless you choose another.

A Service User can hold these roles:

- `developer`, the read/write [Developer](/iam/rbac/#developer) role.
- `developer-readonly`, the read-only [Developer](/iam/rbac/#developer) role.
- `team-manager`, the Manager [Team](/iam/rbac/#team) role.

A Service User can't hold `developer` and `developer-readonly` at the same time.
Service Users can't be Administrators or have billing access.

Only Administrators can set a Service User's roles.
Set them with the `roles` field when you create or update a Service User through the [API](/api-reference/service-users).
Any role other than `developer` requires a plan that includes RBAC.

A Service User's roles limit what its personal access tokens can do.
They don't restrict its API keys.

## Event logs

When a Service User takes actions against your ngrok account, the event log records it as the [Principal](/obs/events/#principal-object).
This helps you isolate what an automated service is doing with your ngrok account, especially when there are multiple such services.

## Service Users pricing

Service Users are available on Pay-as-you-go plans only.
