If you're more comfortable using Docker Compose, you can use the following as a starting point. Copy the contents below into a new file named `docker-compose.yaml`, then run `docker compose up` in that directory.

This Docker Compose file assumes you have an `ngrok.yml` file in the same directory with at least one endpoint defined. See the [ngrok agent config file documentation](/gateway/agent/config/) for help creating a configuration file. To reuse the same configuration file as your local ngrok agent, find the default config file's location with `ngrok config check`.

```yaml
services:
  ngrok:
    image: ngrok/ngrok:latest
    restart: unless-stopped
    command:
      - "start"
      - "--all"
      - "--config"
      - "/etc/ngrok.yml"
    volumes:
      - ./ngrok.yml:/etc/ngrok.yml
    ports:
      - 4040:4040
```

If you define your endpoints directly in `docker-compose.yaml` rather than using an `ngrok.yml` file, the configuration looks a little different. The command runs an `ngrok http` command, and on Mac or Windows you point it at the special URL `host.docker.internal` so the container can reach a service on your host (see [Networking on Docker Desktop](https://docs.docker.com/desktop/features/networking/networking-how-tos/)). The following example runs ngrok alongside the `dockersamples/static-site` image.

```yaml
services:
  static-site:
    image: dockersamples/static-site
    build: .
    ports:
      - "80:80"
    restart: always
  ngrok:
    image: ngrok/ngrok:latest
    command:
      - "http"
      - "http://host.docker.internal:80"
    environment:
      NGROK_AUTHTOKEN: ${NGROK_AUTHTOKEN}
    ports:
      - 4040:4040
```
