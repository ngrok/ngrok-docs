title: Use Any Model with Any SDK
description: Call any supported model from the OpenAI, Anthropic, Google Gen AI, or AWS SDK, and learn what the AI Gateway translates between API formats.
---

You can keep using the OpenAI SDK and route its requests through the AI Gateway to models from other providers, such as Anthropic's Claude models.
Set the SDK's base URL to `https://gateway.ngrok.ai/v1` and its API key to an [access key](/ai-gateway/concepts/access-keys), then change only the `model`, such as `anthropic:claude-sonnet-4-6`.
The same works from the Anthropic, Google Gen AI, and AWS SDKs.

Each SDK speaks one API format, and each model serves only some formats.
When the model you pick doesn't serve your SDK's format, the AI Gateway translates the request if it can, calls the model in a format it serves, and translates the response back.
Your code, your stream reader, and your tool loop stay the same, and you change only the model.

Translation works with every access key and needs no setup.
You pay the rates of the model that served the request, and translation adds no fee.

<Info>
Translation is a quick way to reach many models from one SDK, but API formats don't always match feature for feature.
When the target format has no place for a field or a tool, the gateway removes it or skips the model, as the rest of this page describes.
For the best compatibility with a model's features, call it from the SDK for the model's own API format.
The gateway translates only when it has to, and sends a request to the provider as it is whenever the model serves your SDK's format.
</Info>

## What you'll need

- An [access key](/ai-gateway/concepts/access-keys) from the [Quickstart](/ai-gateway/quickstart).
- The Anthropic SDK for Python or TypeScript, as shown in [Anthropic SDK](/ai-gateway/sdks/anthropic#installation).

## Call an OpenAI model from the Anthropic SDK

OpenAI models don't serve the Anthropic Messages API, so this request goes through translation.

<Steps titleSize="h3">
  <Step title="Send the request">
    Set the model to an OpenAI model.
    The rest of the request is a normal Messages request.

    <CodeGroup>
    ```python Python highlight={9}
    import anthropic

    client = anthropic.Anthropic(
        base_url="https://gateway.ngrok.ai",
        api_key="ng-xxxxx-g1-xxxxx"  # Your access key
    )

    raw = client.messages.with_raw_response.create(
        model="openai:gpt-5.5",
        max_tokens=1024,
        messages=[{"role": "user", "content": "Hello!"}]
    )
    message = raw.parse()

    print(raw.headers.get("ngrok-aig-model"))
    print(message.content[0].text)
    ```

    ```typescript TypeScript highlight={10}
    import Anthropic from "@anthropic-ai/sdk";

    const client = new Anthropic({
      baseURL: "https://gateway.ngrok.ai",
      apiKey: "ng-xxxxx-g1-xxxxx",  // Your access key
    });

    const { data: message, response } = await client.messages
      .create({
        model: "openai:gpt-5.5",
        max_tokens: 1024,
        messages: [{ role: "user", content: "Hello!" }],
      })
      .withResponse();

    console.log(response.headers.get("ngrok-aig-model"));
    console.log(message.content[0].type === "text" ? message.content[0].text : "");
    ```
    </CodeGroup>
  </Step>

  <Step title="Confirm which model answered">
    The `Ngrok-AIG-Model` [response header](/ai-gateway/how-it-works#response-headers) names the OpenAI model that served the request.
    The body is a Messages response, so `message.content` holds a `text` block as it does for a Claude model.

    In [app.ngrok.ai](https://app.ngrok.ai), open the request in [Request details](/ai-gateway/observability/index#inspect-a-request-in-app-ngrok-ai).
    The **Attempts** tab marks the attempt as translated, shows the API format the gateway translated it to, and lists the parameters the gateway changed.
  </Step>
</Steps>

Streaming works the same way.
Call `client.messages.stream(...)` with the OpenAI model, and you get Messages stream events.

## Supported API formats

The gateway translates between these formats in both directions, for buffered and streamed requests:

| Format | Endpoint | SDKs |
|--------|----------|------|
| OpenAI Chat Completions | `/v1/chat/completions` | [OpenAI SDK](/ai-gateway/sdks/openai), [Vercel AI SDK](/ai-gateway/sdks/vercel-ai-sdk), [LangChain](/ai-gateway/sdks/langchain) |
| OpenAI Responses | `/v1/responses` | [OpenAI SDK](/ai-gateway/sdks/openai#supported-endpoints) |
| Anthropic Messages | `/v1/messages` | [Anthropic SDK](/ai-gateway/sdks/anthropic) |
| Gemini generateContent | `/v1beta/models/{model}:generateContent` | [Google Gen AI SDK](/ai-gateway/sdks/google) |
| Bedrock Converse | `/model/{model}/converse` and `/model/{model}/converse-stream` | [AWS SDK](/ai-gateway/providers/bedrock) |

Translation reaches every model in the [model catalog](/ai-gateway/reference/model-catalog) that serves one of these formats.
It also reaches [models you run yourself](/ai-gateway/guides/use-a-model-you-run-yourself), through the API format you set on the custom provider.

In the [List Models API](/ai-gateway/api-reference/models/list), `supported_api_formats` lists the formats a provider serves for a model directly.
`translated_api_formats` lists the other formats that reach the model through translation.

## How the gateway picks a format

The gateway decides for each model when it tries that model:

1. If a provider of the model serves your SDK's format, the gateway sends the request as it is, with no translation.
2. If no provider does, the gateway tries the formats the model serves in this order: Anthropic Messages, Gemini generateContent, OpenAI Chat Completions, OpenAI Responses, then Bedrock Converse.
   It moves to the next format only when it can't translate the request into the one before.

A provider's own format comes first because a compatibility endpoint can drop features such as reasoning signatures and cache hints.
You can't choose the format yourself.

### Fallback models

The gateway checks each [fallback model](/ai-gateway/guides/configure-fallback-models) when it tries that model, so one list can mix providers and formats:

```bash
curl https://gateway.ngrok.ai/v1/messages \
  -H "x-api-key: ng-xxxxx-g1-xxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic:claude-sonnet-4-6",
    "models": ["openai:gpt-5.5", "google:gemini-3.6-flash"],
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

Whichever model serves the request, the response comes back as a Messages response.
If the gateway can't translate the request for one model, it skips that model and tries the next one.

## What translates

The gateway translates these parts of a request:

- System prompts and instructions.
- Text messages and multi-turn conversations.
- Images.
  Converse models take only base64 image data, not an image URL.
- Function tools, tool calls, and tool results.
- Web search, code execution, and remote MCP servers, as [hosted tools](#hosted-tools) describes.
- The settings in the table that follows.

It translates these parts of a response:

- Text, tool calls, and reasoning.
- Web search sources, and the code and results of code execution.
- Streaming events.
- Token usage.
- Stop reasons, such as end of turn, max tokens, and tool use.
- Provider errors.
  The gateway returns the status code and error type your SDK expects for that failure, and keeps the retry hints, so your SDK retries as it does for a native request.

This table shows the name of each translated setting in each format.
A dash means the format has no such setting, so the gateway removes it.

| Setting | Chat Completions | Responses | Messages | generateContent | Converse |
|---------|------------------|-----------|----------|-----------------|----------|
| Max output tokens | `max_completion_tokens` or `max_tokens` | `max_output_tokens` | `max_tokens` | `generationConfig.maxOutputTokens` | `inferenceConfig.maxTokens` |
| Temperature | `temperature` | `temperature` | `temperature` | `generationConfig.temperature` | `inferenceConfig.temperature` |
| Top P | `top_p` | `top_p` | `top_p` | `generationConfig.topP` | `inferenceConfig.topP` |
| Top K | — | — | `top_k` | `generationConfig.topK` | — |
| Stop sequences | `stop` | — | `stop_sequences` | `generationConfig.stopSequences` | `inferenceConfig.stopSequences` |
| Seed | `seed` | — | — | `generationConfig.seed` | — |
| JSON output | `response_format` | `text.format` | `output_config.format` | `generationConfig.responseMimeType` and `responseJsonSchema` | Not translated |
| Tools | `tools` | `tools` | `tools` | `tools[].functionDeclarations` | `toolConfig.tools` |
| Tool choice | `tool_choice` | `tool_choice` | `tool_choice` | `toolConfig.functionCallingConfig` | `toolConfig.toolChoice` |
| Parallel tool calls | `parallel_tool_calls` | `parallel_tool_calls` | `tool_choice.disable_parallel_tool_use` | — | — |
| Reasoning effort | `reasoning_effort` | `reasoning.effort` | `output_config.effort` | `generationConfig.thinkingConfig.thinkingLevel` | — |
| Thinking budget | — | — | `thinking.budget_tokens` | `generationConfig.thinkingConfig.thinkingBudget` | — |

The gateway doesn't translate JSON output to or from Converse yet, so a request that asks for JSON output skips Converse models.

### Hosted tools

[Hosted tools](/ai-gateway/concepts/hosted-tools) run on the provider's servers.
The gateway translates these hosted tools:

| Tool | Chat Completions | Responses | Messages | generateContent | Converse |
|------|------------------|-----------|----------|-----------------|----------|
| Web search | Some providers, as the rules below describe | `web_search`, `web_search_preview` | `web_search_20250305` and later versions | `google_search` | — |
| Code execution | — | `code_interpreter` | `code_execution_20250522`, from Messages only | `code_execution` | — |
| Remote MCP servers | — | `mcp` | `mcp_servers` with the `mcp_toolset` tool | — | — |

A dash means the format has no such tool, so the gateway skips a model that serves only that format.

These rules apply to translated hosted tools:

- **Web search on Chat Completions models**: Chat Completions has no standard search tool, so only some providers can search.
  The gateway sends the search as `web_search_options` to OpenAI search models, as `browser_search` to Groq, and as a `web_search` tool to Z.ai.
  For Moonshot, the gateway runs Moonshot's search call for the model and bills both calls as one request.
  The gateway skips Chat Completions models from other providers.
- **Search options**: `user_location` and `search_context_size` reach OpenAI models.
  For other targets, the gateway removes them.
  Allowed and blocked domain lists don't translate to Chat Completions or Gemini models, so the gateway skips those models.
- **Search results**: A Messages client gets the sources of a search from another format as a list at the end of the text, not as citation blocks.
  Other clients get citations in their own format, in buffered and streamed responses.
- **Code execution**: Code tools translate only between formats whose tool runs Python.
  Responses and Gemini models reach each other, and a Messages request with `code_execution_20250522` reaches either.
  Claude models run code through Bash, so a translated request with a code tool never reaches a Claude model.
  Your SDK gets the code the model ran and its result as typed items, not as text.
  Files a code run makes, such as charts, don't come back when your format has no place for them.
- **Remote MCP servers**: MCP translates between Responses and Messages, for Claude models that Anthropic serves directly.
  Set `require_approval` to `never`, because the Messages API has no approval step.
  The gateway skips a Messages model when an MCP tool needs your approval.
- **Conversation history**: When you send earlier search results and citations back on the next turn, a model from another provider gets them as plain text.
- **Billing**: Hosted tools bill at the rate of the tool the provider ran, not the tool your SDK named.

Other hosted tools, such as file search, image generation, URL context, Bash, the text editor, and web fetch, don't translate.

## Removed and changed parameters

The gateway removes or changes a parameter when the target format or model can't take it as you sent it.
It lists each parameter it removed or changed in the `Ngrok-AIG-Removed-Params` [response header](/ai-gateway/how-it-works#response-headers), and in the **Attempts** tab of [Request details](/ai-gateway/observability/index#inspect-a-request-in-app-ngrok-ai).
The header doesn't list a value the gateway adds, such as `max_tokens` for a Messages model.

Fields that only one format defines don't translate.
For example, `frequency_penalty`, `logit_bias`, `metadata`, `service_tier`, and Gemini `safetySettings` reach only a model that serves your SDK's format.
For other models, the gateway removes them.

These rules add or change a value:

- **Max tokens on Messages models**: The Messages API requires `max_tokens`.
  If your request doesn't set a limit, the gateway sends the model's maximum output tokens.
  Your account's [max output tokens](/ai-gateway/guides/account-settings) setting still applies.
  Set your own limit if you need responses to stop at the same length on every model.
- **Sampling settings on Messages models**: The gateway lowers a temperature above 1 to 1.
  If you send both `temperature` and `top_p`, the gateway removes `top_p`.
  Claude models refuse `temperature` and `top_k` while thinking is on, and need a `top_p` of 0.95 or more.
  So when a thinking budget or a reasoning effort turns on thinking, the gateway removes `temperature` and `top_k`, and raises a `top_p` below 0.95 to 0.95.
- **Thinking budget on Messages models**: Messages counts thinking inside `max_tokens`.
  When your budget is larger than the output limit, the gateway lowers the budget so the model still has room to answer.
- **Reasoning effort**: The gateway lowers an effort level the target doesn't have, such as `max`, to `high`.
- **Responses models**: The gateway raises a `max_output_tokens` below 16 to 16.
  It also sends `store: false`, because your SDK can't read a stored response back.
- **Tool schemas**: The gateway removes `strict` for formats that have no strict mode, so the model can return arguments that don't match your schema exactly.
  It removes Gemini's `propertyOrdering` for other formats.
- **Image detail**: Only Chat Completions and Responses take an image `detail` setting.
  Other models get the image at their default detail.

Reasoning settings translate in these ways:

- A reasoning effort reaches every model that can reason, except Converse models.
- Claude Haiku 4.5, Claude Sonnet 4.5, Claude Opus 4.5, and Claude Opus 4.1 take a thinking budget, not an effort.
  For these models, the gateway turns on thinking with a budget for your effort level: 1,024 tokens for `minimal` and `low`, 4,096 for `medium`, 16,384 for `high`, and 32,000 for `xhigh` and `max`.
  A budget only approximates an effort, so the gateway lists the effort in the header.
- A thinking budget reaches Claude and Gemini models.
  OpenAI and Converse models take no budget, so the gateway removes it.
- Reasoning blocks from an earlier turn go back only to the format that produced them, because a provider rejects another provider's reasoning signature.
  The gateway removes them for any other format.

Prompt caching markers, such as `cache_control`, reach a model only through the Messages API.
For a model the gateway calls in another format, it removes them.
The response stays the same, but the request can cost more, because the provider doesn't cache the prompt where you marked it.

Provider-specific request headers, such as `anthropic-beta` and `OpenAI-Organization`, don't reach a model the gateway translated the request for.

## When the gateway skips a model

The gateway skips a model, without calling it, when it can't translate the request for that model:

- The request has file, document, audio, or video input.
  Only text and images translate.
- The request has an image URL, and the target is a Converse model.
  Send the image as base64 data instead.
- The request has a hosted tool that the target format doesn't have, or that doesn't translate.
  See [hosted tools](#hosted-tools).
- The request sets `max_uses` for web search, and the target is a Gemini, Groq, or Z.ai model.
- The request has web search with JSON output, and the target is a Claude model.
- The request has web search with function tools or JSON output, and the target is a Gemini 2.x or earlier model.
- The request has code execution with function tools or `tool_choice`, and the target is a Gemini model.
- The request has code execution with JSON output, and the target is a Gemini 2.x or earlier model.
- The request points to state the provider stores, such as `previous_response_id`, `conversation`, `prompt`, or `background: true` in the Responses API.
  Send the full conversation instead.
- The request asks for more than one answer, such as `n` or `candidateCount` greater than 1.
- The request uses the legacy Chat Completions `functions` or `function_call` fields.
  Use `tools` and `tool_choice` instead.
- The last message is an assistant message that the model should continue.
- The request asks for JSON output with no schema, or with a schema `description`, and the target is Messages.
- The request has a Gemini `responseSchema`.
  Send the same schema as JSON Schema in `responseJsonSchema` to reach other models.
- The request has a Converse `guardrailConfig`, `outputConfig`, `promptVariables`, or `cachePoint`.
- A [Firewall](/ai-gateway/concepts/firewall) policy applies to the request, because Firewall can't check a translated response yet.

If every model in the request is skipped, the gateway returns [`ERR_NGROK_27228`](/ai-gateway/reference/error-codes#err_ngrok_27228) with the reason for each model.
To fix it, remove the field the message names, or pick a model that serves your SDK's format.
