ngrok.ai maintains a catalog of known providers and models.
This catalog enables automatic model resolution, routing, model validation, and rich metadata for selection strategies.

## How the catalog works

When you send a request with a model name like `gpt-4o`, the gateway automatically:

1. Resolves the model using the catalog
2. Finds every provider that serves the model, with the model author's own provider (for example, OpenAI) first, and applies the right provider credentials
3. Routes the request to the provider’s endpoint

If you want to explicitly select a provider, use the `provider:model` format in the model string.
For example:

```json
{
  "model": "openai:gpt-4o",
  "messages": [{"role": "user", "content": "Hello"}]
}
```

## Built-in providers

The catalog includes built-in providers—public AI APIs with known models and routing metadata.
You can manage them on the [Providers page](https://app.ngrok.ai/providers).

### Authentication

Send traffic using an [access key](/ai-gateway/concepts/access-keys).
This key authenticates your requests to the gateway, not to the upstream provider.

### Billing and provider credentials

The AI Gateway splits billing into two parts: using the gateway and paying the model provider.

Many built-in models don’t need a provider key.
You can spot them in the tables below: if **Needs BYOK?** says “No,” you can use the model right away as long as you have credits.
The gateway takes care of authentication and charges your credits.
Availability is per model, so a provider can have some models you can pay for with credits and some you can't.

Other providers do need a key.
For those, add your provider key in app.ngrok.ai.
The provider bills you directly for model usage, and your credits cover the gateway fee.
This is often called BYOK (bring your own key).

LLM API can send a request to a different upstream than the one the model names, and it bills that upstream's price.
A model works with credits only when no upstream charges more than the catalog price.
Models with long-prompt price tiers, separate cache-write prices, or image input priced apart from text need your own LLM API key, and that includes every Claude model.

## Using models from the catalog

### Simple model reference

Reference models directly by their ID.
A bare ID such as `gpt-4o` resolves to every provider that serves the model.
The full catalog ID, such as `openai/gpt-4o`, works too:

```json
{
  "model": "gpt-4o",
  "messages": [{"role": "user", "content": "Hello"}]
}
```

### Explicit provider

Use the `provider:model` format for explicit routing:

```json
{
  "model": "openai:gpt-4o",
  "messages": [{"role": "user", "content": "Hello"}]
}
```

## Custom providers

Built-in providers cover major public APIs.
For self-hosted models (Ollama, vLLM, LM Studio) or other endpoints, create a **custom provider** in the **Custom** tab in app.ngrok.ai.
Custom providers always require a provider key when the upstream needs authentication.

See [Custom providers](/ai-gateway/concepts/custom-providers) to add one.

## Catalog updates

ngrok.ai updates the model catalog periodically to include new models and providers.
The tables on this page leave out models that their provider has retired.
To use a model that isn't in the catalog yet, send it with its provider prefix, such as `groq:new-model-id`.
The gateway passes it through to that provider.
Uncataloged models need your own provider key, because ngrok.ai can't price them, so you can't pay for them with credits.
