This directory contains scripts used to automate certain aspects of the docs site.
For example, `parse-integrations` generates integrations metadata that you can use to display the integrations hub at `/integrations`.

## Homepage changelog

`fetch-homepage-changelog.py` fetches `https://ngrok.com/changelog/rss.xml` and writes the three newest distinct entries to `snippets/homepage-changelog.mdx`.
The homepage imports that snippet.
The script uses only Python's standard library.

Run locally:

```sh
python3 custom/scripts/fetch-homepage-changelog.py
python3 -m unittest discover -s custom/scripts/tests -p 'test_homepage_changelog.py'
```

The **Update homepage changelog** GitHub Action runs when a PR opens, receives a commit, reopens, or becomes ready for review.
It updates the same PR branch only when the generated content changes.
It uses the existing `NGROK_DOCS_BOT_APP_ID` and `NGROK_DOCS_BOT_PRIVATE_KEY` secrets so the bot commit can trigger CI and Mintlify previews.
The bot's follow-up run produces no commit if the feed is unchanged.
Fork and Dependabot PRs don't receive automatic updates.

The action checks out the event's exact head commit and uses a normal push.
If someone updates the branch during the run, the push fails instead of overwriting their work; the newer PR event starts another run.

Failed requests, malformed feeds, invalid entry URLs or dates, and feeds with fewer than three distinct entries fail the check and leave the previous snippet intact.
Require the `refresh` job in branch protection if merges must wait for a successful refresh.
Otherwise, a failed check doesn't itself prevent a merge.

This is a PR-time snapshot, not a Mintlify build hook.
An unchanged PR doesn't refresh merely because it merges or Mintlify rebuilds it.
The workflow doesn't add a schedule, a separate PR, or a direct push to the deployment branch.
The first successful fetch replaces the committed initial snapshot.

## Image sizes

`check-image-sizes.sh` fails on images over 500 KB and warns on images over 200 KB.
The **Check image sizes** GitHub Action runs it on every image a PR adds or modifies, so existing images don't block unrelated PRs.
Mintlify's CDN already resizes content images and converts them to modern formats, so this check mainly keeps oversized originals out of the repo.

Check every image in the repo, or specific files:

```sh
pnpm check-images
bash custom/scripts/check-image-sizes.sh img/docs/my-diagram.png
```

To shrink an image, export screenshots at 1x or 2x rather than larger, and compress PNGs with a tool such as [Squoosh](https://squoosh.app), `pngquant`, or `oxipng`.
Set `IMAGE_MAX_KB` or `IMAGE_WARN_KB` to change the limits.

## Traffic Policy action list

`gateway/traffic-policy/actions.json` is the source of truth for the list of Traffic Policy actions.
It's published at `https://ngrok.com/docs/gateway/traffic-policy/actions.json` for agents and tools, such as the [ngrok agent skills](https://github.com/ngrok/skills), so keep each entry's `type` and `url` stable.

Each action's page lives at `gateway/traffic-policy/actions/<type>.mdx`, so its URL path is the same as the `type` you use in a Traffic Policy document.
`traffic-policy-actions.js` checks that convention, and that each entry's `type` and `phases` match the `### Type` and `### Supported phases` sections of its action page.
It then generates two snippets that `gateway/traffic-policy/actions/index.mdx` imports:

- `snippets/traffic-policy/actions-data.jsx`: the data for the interactive action hub that people see.
- `snippets/traffic-policy/actions-list.mdx`: a Markdown table that only the `.md` version of the page shows.

When you add or change an action, edit `actions.json`, then regenerate the snippets:

```sh
pnpm traffic-policy-actions
```

The **CI Checks** GitHub Action runs `pnpm traffic-policy-actions --check`, which fails when `actions.json` disagrees with an action page or the snippets are out of date.

## Pages generated from monorepo data

The ngrok monorepo ships facts as JSON in `data/generated/`, and this repository owns how they're presented.
Three scripts build pages from that data:

- `generate-error-pages.js` reads `errors.json` and writes every `errors/err_ngrok_*.mdx` page and the `snippets/errors/_err_ngrok_list.mdx` table.
- `generate-cli-pages.js` reads `cli.json` and writes `gateway/agent/cli.mdx` and `gateway/agent/cli-api.mdx`.
- `generate-event-pages.js` reads `events.json` and writes `snippets/obs/_event-types-tables.mdx`, which `obs/events/reference.mdx` imports, and the field table of each API object it uses.

Each script also removes the files of anything that's no longer in the data.
Don't edit the generated files, because the next run overwrites them.
Add or edit prose in `custom/` instead:

- `custom/errors/details/err_ngrok_<code>.mdx` explains an error, after its message.
- `custom/errors/pages/err_ngrok_<code>.mdx` replaces the generated top of an error page.
- `custom/cli/commands/<command>.mdx` goes after a command's description, such as `ngrok-config-add-authtoken.mdx`.

Mintlify doesn't serve `custom/errors/` or `custom/cli/`, so these files only appear on the pages they're part of.

Regenerate the pages:

```sh
pnpm run generate-error-pages
pnpm run generate-cli-pages
pnpm run generate-event-pages
```

To list the errors that have no explanation yet, run `pnpm run generate-error-pages --missing`.

The **Auto-generate Docs PR** GitHub Action runs the scripts whenever the monorepo pushes to `ngrokrock/dev-gen-changes`, so the auto-generated docs PR holds both the data and the pages.
The **CI Checks** GitHub Action runs each script with `--check`, which fails when a committed file doesn't match the data and the prose in `custom/`.

## Errors llms.txt

Mintlify's generated `llms.txt` only lists pages in the navigation, so it doesn't include the individual `errors/err_ngrok_*` pages.
`generate-errors-llms-txt.js` reads those pages' frontmatter and writes `errors/llms.txt`, which links to one sub-index per error code range at `errors/llms/<range>/llms.txt`.
Mintlify serves these as static files, such as `https://ngrok.com/docs/errors/llms.txt`.
Every file must be named `llms.txt`: Mintlify only serves other `.txt` files on Enterprise plans.
It also lists every error page in a hidden, searchable `Error codes` group under the Errors navigation in `docs.json`.
The pages stay out of the sidebar, but Mintlify includes them in its generated `llms.txt`, `sitemap.xml`, site search, and AI assistant.
The script rewrites that group on every run, so don't edit it by hand.

Run locally:

```sh
pnpm run generate-errors-llms
```

The **Update errors llms.txt** GitHub Action runs on PRs that change `errors/**` or the script, including the auto-generated docs PRs.
It commits the regenerated files to the same PR branch when they change, the same way as the homepage changelog action.

## Docs llms.txt

The root `llms.txt` replaces the one Mintlify generates, and it's written by hand.
It links to Mintlify's generated `/_llms/` indexes for Gateway, AI Gateway, Integrations, and Reference.
Mintlify lists the pages in the Start, Share Localhost, For AI Agents, and Pricing tabs directly in its own root instead of in an index, so `llms.txt` lists them by hand.

`check-llms-txt.js` fails when a page in one of those tabs isn't linked from `llms.txt`, or when `llms.txt` links to a docs page that doesn't exist or is marked `noindex` or `hidden`.
The **CI Checks** GitHub Action runs it on every push. Run it locally:

```sh
pnpm check-llms-txt
```
