An **ngrok Endpoint** is the network address clients use to reach a service through ngrok.
Choose between two endpoint types based on who manages the endpoint and how long it should stay online.

| Endpoint type | How it is managed | When to choose it |
| --- | --- | --- |
| [Agent Endpoint](/gateway/endpoints/agent-endpoints) | Created by an Agent CLI, SDK, or Kubernetes Operator; it stays online while the agent is connected and forwards traffic to that agent by default. | Choose it when the agent runs near your service, including on a laptop, private network, or cluster. |
| [Cloud Endpoint](/gateway/endpoints/cloud-endpoints/) | Created through the dashboard, API, or Kubernetes Operator; it stays online until you delete it and requires a Traffic Policy to handle traffic. | Choose it for a persistent entry point with centrally managed Traffic Policy. |

Agent Endpoints can use a randomly assigned URL or a URL you choose.
Cloud Endpoints require a fully qualified URL.
Cloud Endpoint Traffic Policy can forward traffic to an [internal endpoint](/gateway/endpoints/internal-endpoints/) or return a response.

## Create an endpoint

- To expose a service reachable from an agent, follow the [Agent CLI Quickstart](/gateway/endpoints/agent-cli-quickstart/).
- To create a persistent Cloud Endpoint, follow the [Cloud Endpoints Quickstart](/getting-started/cloud-endpoints-quickstart).

## Configure an endpoint

Endpoints use a [protocol](/gateway/endpoints/protocols) to determine the traffic they accept and a [binding](/gateway/endpoints/bindings) to control where that traffic can originate.
Learn about [public endpoints](/gateway/endpoints/public-endpoints) and [Kubernetes endpoints](/gateway/endpoints/kubernetes-endpoints) in the shared reference pages.
See the [Internal Endpoints guide](/gateway/endpoints/internal-endpoints) for both Agent and Cloud Endpoint setup.

## Route and scale traffic

Use [Traffic Policy](/gateway/traffic-policy/) to apply routing and other behavior to an endpoint.
Enable [Endpoint Pooling](/gateway/endpoints/endpoint-pooling) to distribute traffic among endpoints that share a URL and binding.
See the [load balancing across multiple clouds guide](/gateway/endpoints/load-balancing-multiple-clouds) for an example.

## Pricing

Free and Hobbyist plans include endpoint usage credit.
On the Pay-as-you-go plan, active endpoints are charged per endpoint hour.
See [Endpoint pricing](/pricing-limits/#endpoint-limits) for plan details.
