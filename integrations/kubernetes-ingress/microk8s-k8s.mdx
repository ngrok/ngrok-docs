This guide shows you how to add public ingress to an app running on a Canonical MicroK8s cluster.
You'll use the [ngrok Kubernetes Operator](/gateway/k8s/) with the Kubernetes Gateway API to route public traffic to the app through an encrypted tunnel.

## What you'll need

- A MicroK8s cluster reachable with `kubectl`.
  MicroK8s runs on a local workstation, an IoT device, a cloud virtual machine, or any system running one of [the supported Linux flavors](https://snapcraft.io/microk8s).
  If you don't have a cluster yet, follow Canonical's [MicroK8s get-started guide](https://canonical.com/microk8s/docs/getting-started).
- An ngrok account.
- `kubectl` installed on your local workstation.
- The [ngrok Kubernetes Operator](/gateway/k8s/) installed on your cluster, along with the Gateway API CRDs.
- A reserved domain from the ngrok [dashboard](https://dashboard.ngrok.com/domains) or [API](/api-reference/reserveddomains/list); this guide refers to it as `NGROK_DOMAIN`.

<Steps titleSize="h2">
  <Step title="Confirm your cluster is ready">

    Check that MicroK8s is running before you deploy anything:

    ```bash
    microk8s status --wait-ready
    ```

    If you see `microk8s is running`, your cluster is ready.
  </Step>

  <Step title="Deploy an example app">

    Create a manifest named `tinyllama.yaml` with the following YAML.
    It defines a service and deployment for the [tinyllama](https://github.com/ngrok-samples/tinyllama) demo LLM app.

    ```yaml tinyllama.yaml showLineNumbers
    apiVersion: v1
    kind: Service
    metadata:
      name: tinyllama
      namespace: default
    spec:
      ports:
        - name: http
          port: 80
          targetPort: 8080
      selector:
        app: tinyllama
    ---
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: tinyllama
      namespace: default
    spec:
      replicas: 1
      selector:
        matchLabels:
          app: tinyllama
      template:
        metadata:
          labels:
            app: tinyllama
        spec:
          containers:
            - name: tinyllama
              image: ghcr.io/ngrok-samples/tinyllama:main
              ports:
                - name: http
                  containerPort: 8080
    ```

    Apply the manifest to your cluster:

    ```bash
    kubectl apply -f tinyllama.yaml
    ```
  </Step>

  <Step title="Create a GatewayClass">

    A [GatewayClass](https://gateway-api.sigs.k8s.io/api-types/gatewayclass/) tells Kubernetes which controller manages your [Gateways](https://gateway-api.sigs.k8s.io/api-types/gateway/).
    This one assigns them to the ngrok Kubernetes Operator.

    Create a file named `gatewayclass.yaml` with the following YAML:

    ```yaml gatewayclass.yaml
    apiVersion: gateway.networking.k8s.io/v1
    kind: GatewayClass
    metadata:
      name: ngrok
    spec:
      controllerName: ngrok.com/gateway-controller
    ```

    Apply it to your cluster:

    ```bash
    kubectl apply -f gatewayclass.yaml
    ```
  </Step>

  <Step title="Route traffic to the app">

    The Gateway listens for requests to `NGROK_DOMAIN`, and the [HTTPRoute](https://gateway-api.sigs.k8s.io/api-types/httproute/) sends those requests to the `tinyllama` service.

    Create a file named `tinyllama-gateway.yaml` with the following YAML, replacing `NGROK_DOMAIN` with your reserved domain:

    ```yaml tinyllama-gateway.yaml showLineNumbers
    apiVersion: gateway.networking.k8s.io/v1
    kind: Gateway
    metadata:
      name: tinyllama-gateway
      namespace: default
    spec:
      gatewayClassName: ngrok
      listeners:
        - name: tinyllama-web
          protocol: HTTP
          port: 80
          hostname: "NGROK_DOMAIN"
          allowedRoutes:
            namespaces:
              from: Same
    ---
    apiVersion: gateway.networking.k8s.io/v1
    kind: HTTPRoute
    metadata:
      name: tinyllama-route
      namespace: default
    spec:
      parentRefs:
        - group: gateway.networking.k8s.io
          kind: Gateway
          name: tinyllama-gateway
          namespace: default
      hostnames:
        - "NGROK_DOMAIN"
      rules:
        - matches:
            - path:
                type: PathPrefix
                value: /
          backendRefs:
            - name: tinyllama
              kind: Service
              port: 80
    ```

    Apply the Gateway and HTTPRoute:

    ```bash
    kubectl apply -f tinyllama-gateway.yaml
    ```
  </Step>

  <Step title="Test your app">

    Open `https://NGROK_DOMAIN` in a browser.
    The ngrok Kubernetes Operator routes the request from ngrok's network to the `tinyllama` service, so you can reach the app from any device or network.
  </Step>
</Steps>

## What's next?

You've used the open source ngrok Kubernetes Operator to add public ingress to an app on MicroK8s with the Kubernetes Gateway API.
Because ngrok handles ingress and middleware execution, you can follow the same process for your production apps.

To go further, explore the [Kubernetes docs](/gateway/k8s/) for how the Operator works and how to integrate ngrok with an existing production cluster, or try [bindings](/gateway/k8s/guides/bindings/) and [endpoint pooling](/gateway/k8s/guides/pooling/).
